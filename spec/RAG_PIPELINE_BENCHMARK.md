# RAG Pipeline 竞品对比与借鉴评估

> 状态：✅ 已完成 · 2026-07-27 · M3 + DeepSeek 两轮对抗式对齐
> **更新 2026-08-04**：检索核心已落地 — `server/rag_index.py`（Markdown 结构分块 + 智谱 embedding-3 索引 + vector/keyword/hybrid 三路检索 + XML context 注入），评测 `scripts/rag_eval.py`。实测 22 条黄金集：vector Recall@1 **0.909** vs keyword 基线 0.273（中文问英文内容，向量检索显著胜出）。详见 `docs/rag_eval_20260804.json`。
> **经验修正**：原「关键词结果在前 + 向量追加」的 hybrid 合并策略在实践中失效（噪音关键词把正确结果挤出 top-k），改为「向量为基 + 关键词加成」。长/短记忆压缩仍在 roadmap。
> **更新 2026-08-05**：中文 keyword 检索增强 — `_keyword_score` 增加相邻汉字 bigram 命中加权（0.15/个，无依赖近似分词），修复中文无空格导致 `q.split()` 分词退化为整句匹配的问题。实测 22 条黄金集：keyword Recall@1 **0.273→0.409**（MRR 0.318→0.441），hybrid Recall@1 保持 **0.909**（MRR 0.955→0.947，差异为同主题多来源笔记的黄金集判定歧义，非检索质量下降）。详见 `docs/rag_eval_20260805.json`。

## 核心发现

### 1. Knowledge Lab 与四者不在同一象限

四者解决"找到知识"（Chat-First），Knowledge Lab 解决"记住知识"（Quiz-First）。

### 2. Pipeline 差异根因

| Knowledge Lab 不做 | 根本原因 |
|-------------------|---------|
| Chunking | 笔记已由 LLM 结构化，是自然语义单元，无需切分 |
| Embedding | 检索目标是"出题素材"而非"相似度匹配"，关键词命中更可控 |
| 向量检索 | vault 规模小（个人量级），全文扫描 O(N×L) 在 N<1000 时 <50ms |
| Rerank | 个人场景召回量 <10，边际收益极低 |
| 高并发 | 个人单用户，Python stdlib ~50 QPS 完全够用 |

### 3. 不可被复制的护城河

**Quiz-First 范式 + SM-2 闭环** — 让 LLM 出题、判分、驱动间隔重复，四款 RAG 产品都不会做这个方向。

## ⚠️ 重要标注：有意识的现阶段不做，而非能力缺位

以下 5 项能力在竞品对比中显示为"劣势"，但**每一项都是基于 Knowledge Lab 当前定位（个人学习工具）的有意识取舍**，不是做不到，而是现阶段不需要：

| 不做项 | 不是缺位，而是 | 什么时候会重新评估 |
|--------|--------------|------------------|
| 无 Chunking | 笔记已由 LLM 结构化，是自然语义单元 | 引入 URL 导入长文 / PDF 场景时 |
| 无 Embedding | 出题场景关键词命中已足够，省去 embedding 成本 | 笔记 > 500 且出现"检索不到"反馈时 |
| 无向量检索 | vault 规模小（198 篇），全文扫描 < 50ms | 笔记 > 1000 且检索体验下降时 |
| 无 Rerank | 个人场景召回量 < 10，边际收益极低 | 检索 Top-10 相关率 < 70% 时（预计永不） |
| 无高并发 | 单用户本地工具，~50 QPS 完全够用 | 转多用户 SaaS 时（不在当前规划内） |

> **核心原则**：每一项"不做"都有明确的触发条件。当触发条件满足时，用最轻方式补（如本地 sqlite-vec + bge-small-zh），而非照搬竞品的全套企业级方案。

## 向量化引入触发条件（量化阈值）

> 状态：⚠️ **现阶段不做** — 有意识的技术负债，非能力缺位
> 决策日期：2026-07-27

### 为什么现在不做

1. **体积膨胀**：向量数据 ≈ 原文 1.5-3 倍，轻量化定位暂不引入额外存储
2. **多一套检索机制**：与"个人学习工具"的简洁定位冲突
3. **关键词检索当前充分**：主题集中在 AI PM 领域，关键词命中率 > 95%

### 推荐演进路径（官方记录）

| Step | 动作 | 触发条件 | 实现方式 |
|:--:|------|---------|---------|
| **0** | 维持现状 | 当前（198 篇笔记，关键词检索充分） | 无 |
| **1** | 轻量语义检索 | 笔记 > 500 且出现"检索不到"反馈 | 本地 `bge-small-zh`（CPU < 50ms，零成本）+ `sqlite-vec` |
| **2** | 引入 Chunking | 出现 URL 导入 / 长文剪藏 / PDF 摘要需求 | 借鉴 RAGFlow 语义边界 + overlap 策略，**仅用于新导入长文，笔记本身不做 chunking** |
| **3** | 评估 Rerank | 召回 Top-10 中相关率 < 70% | 视情况补 Cross-encoder（预计永不触发） |

> **关键原则**：每一步都有明确的、可量化的触发条件。不提前做，不跟风做，不因为"竞品有"而做。

### 与现有检索的关系（Step 1 启动后）

```
搜索请求
  ├── 向量搜索（语义主路，8/4 起已落地：智谱 embedding-3）
  └── 关键词搜索（中文 bigram 增强 · 8/5：keyword/向量加成，去噪兜底）
      └── 结果合并：向量为基 + 关键词命中加成（8/4 修正，替代旧的「关键词在前+向量追加」）
```

| 借鉴项 | 来源 | ROI | 优先级 | 触发条件 |
|--------|------|-----|:--:|---------|
| Chunking | RAGFlow/Dify | 网页剪藏场景必须 | P2 | URL 导入长文时 |
| Embedding | Quivr/AnythingLLM | 中期可观 | P2 | 笔记 >500 且检索不到 |
| 向量检索 | Dify/RAGFlow | 与 Embedding 配套 | P2 | 同上 |
| Rerank | RAGFlow/Dify | 不值得 | P4 | 永不 |
| 高并发 | RAGFlow | 不值得 | P4 | 永不 |

**关键认知**：劣势 ≠ 问题，是定位选择。借鉴的判断标准不是"竞品有没有"，而是"用户在不远的未来会不会因此离开"。
